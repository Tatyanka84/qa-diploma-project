# Отчёт по итогам тестирования

## Краткое описание

Выполнена автоматизация тестирования приложения «Путешествие дня», взаимодействующего с базой данных и симулятором банковских сервисов.

Приложение тестировалось по двум способам оплаты:

- обычная оплата тура банковской картой;
- покупка тура в кредит.

Тестирование проводилось с использованием двух СУБД:

- MySQL;
- PostgreSQL.

Один и тот же набор из 56 автоматизированных тест-кейсов был последовательно запущен с каждой СУБД.

## Количество тест-кейсов

Всего разработано и выполнено 56 автоматизированных тест-кейсов.

Результаты запусков:

- 56 тест-кейсов выполнено с использованием MySQL;
- 56 тест-кейсов выполнено с использованием PostgreSQL.

Таким образом, общее количество выполнений составило 112.

## Процент успешных и неуспешных тест-кейсов

### При работе с СУБД MySQL

- 36 успешных тест-кейсов — 64,28%;
- 20 неуспешных тест-кейсов — 35,72%.

### При работе с СУБД PostgreSQL

- 36 успешных тест-кейсов — 64,28%;
- 20 неуспешных тест-кейсов — 35,72%.

В каждом запуске использовался одинаковый набор из 56 тест-кейсов.

## Покрытые сценарии

В ходе тестирования проверялись:

- успешная оплата банковской картой;
- оплата картой, отклонённая банком;
- успешная покупка в кредит;
- покупка в кредит, отклонённая банком;
- проверка номера банковской карты;
- проверка месяца действия карты;
- проверка года действия карты;
- проверка имени владельца карты;
- проверка поля CVC/CVV;
- проверка сообщений об ошибках;
- проверка статусов операций в базе данных.

## Выявленные баги

В ходе тестирования были выявлены несоответствия между ожидаемым и фактическим поведением приложения.

Неуспешные тесты были зафиксированы в Allure-отчёте и отнесены к категории `Product defects`.

Для определения причин выявленных проблем необходимо провести дополнительный анализ результатов тестирования и повторно проверить приложение после внесения исправлений.

## Подготовленные отчёты

По результатам работы подготовлены:

- отчёт Gradle;
- Allure-отчёт;
- итоговый отчёт по автоматизации тестирования;
- общие рекомендации по результатам тестирования.

## Общие рекомендации

- Устранить дефекты, выявленные в результате тестирования.
- Составить документацию по проекту с подробным описанием функциональности приложения.
- Зафиксировать требования к заполнению полей формы оплаты и покупки в кредит.
- Зафиксировать ожидаемые тексты сообщений об ошибках.
- Добавить стабильные селекторы для элементов интерфейса, например `data-test-id`.
- Проверить корректность сохранения статусов `APPROVED` и `DECLINED` в базе данных.
- Повторно выполнить полный набор из 56 тест-кейсов с MySQL после исправления дефектов.
- Повторно выполнить полный набор из 56 тест-кейсов с PostgreSQL после исправления дефектов.
- Сформировать обновлённые Allure-отчёты по результатам повторного запуска.

## Итог

В рамках проекта было разработано 56 автоматизированных тест-кейсов для проверки обычной оплаты банковской картой и покупки тура в кредит.

Один и тот же набор тестов был запущен с использованием MySQL и PostgreSQL. Всего выполнено 112 запусков тест-кейсов.

При каждом запуске:

- 36 тестов завершились успешно — 64,28%;
- 20 тестов завершились неуспешно — 35,72%.

В ходе тестирования были выявлены баги и несоответствия в работе приложения. Результаты тестирования представлены в отчётах Gradle и Allure.
