# План автоматизации тестирования приложения «Путешествие дня»

## 1. Автоматизируемые сценарии

### Тестовые данные

Для проверки используются следующие карты:

- `4444 4444 4444 4441` — успешная операция, статус `APPROVED`.
- `4444 4444 4444 4442` — отклонённая операция, статус `DECLINED`.

Для остальных полей используются:

- валидный месяц;
- текущий или будущий год;
- корректное имя владельца латиницей;
- трёхзначный код CVC/CVV.

После выполнения операции статус проверяется в базе данных:

- для оплаты картой — таблица `payment_entity`;
- для оплаты в кредит — таблица `credit_request_entity`.

## 2. Позитивные сценарии

### 2.1. Успешная оплата дебетовой картой

1. Открыть приложение по адресу `http://localhost:8080`.

3. Заполнить форму валидными данными карты `4444 4444 4444 4441`.

## 3. Негативные сценарии

Негативные проверки выполняются отдельно для:

- дебетовой оплаты;
- оплаты в кредит.

Во всех негативных сценариях остальные поля заполняются валидными значениями. Изменяется только проверяемое поле.

### 3.1. Номер карты

Проверяются следующие значения:

- пустое поле;
- 15 цифр — значение меньше допустимой длины;
- 16 цифр — валидное значение;
- 17 цифр — значение больше допустимой длины;
- специальные символы;
- незарегистрированный номер карты.

Ожидаемые результаты:

- для пустого, короткого, длинного и некорректного значения отображается сообщение `Неверный формат`;
- для незарегистрированной карты операция отклоняется банком.

### 3.2. Месяц

Проверяются следующие значения:

- пустое поле;
- `00`;
- `01` — минимальное допустимое значение;
- `12` — максимальное допустимое значение;
- `13` — значение за пределами допустимого диапазона;
- трёхзначное значение.

Ожидаемые результаты:

- значения `01` и `12` принимаются как валидные;
- для `00`, пустого и трёхзначного значения отображается сообщение `Неверный формат`;
- для значения `13` отображается сообщение `Неверно указан срок действия карты`.

### 3.3. Год

Проверяются следующие значения:

- пустое поле;
- прошедший год;
- текущий год;
- год через 10 лет;
- трёхзначное значение.

Ожидаемые результаты:

- текущий год и год через 10 лет принимаются как валидные;
- для прошедшего года отображается сообщение `Истёк срок действия карты`;
- для пустого и трёхзначного значения отображается сообщение `Неверный формат`.

### 3.4. Владелец карты

Проверяются следующие значения:

- пустое поле;
- одна буква;
- две буквы;
- значение кириллицей;
- специальные символы.

Ожидаемые результаты:

- для пустого поля отображается сообщение `Поле обязательно для заполнения`;
- значение из одной буквы считается некорректным;
- значение из двух и более допустимых латинских символов принимается;
- кириллица и специальные символы считаются некорректными.

### 3.5. CVC/CVV

Проверяются следующие значения:

- пустое поле;
- две цифры;
- три цифры;
- четыре цифры;
- специальные символы.

Ожидаемые результаты:

- значение из трёх цифр принимается как валидное;
- для пустого поля, двух, четырёх цифр и специальных символов отображается сообщение `Неверный формат`.

### 3.6. Пустая форма

1. Открыть форму оплаты.
2. Не заполнять поля.
3. Нажать кнопку «Продолжить».
4. Проверить сообщения об ошибках во всех полях.

Проверяются сообщения:

- номер карты — `Неверный формат`;
- месяц — `Неверный формат`;
- год — `Неверный формат`;
- владелец — `Поле обязательно для заполнения`;
- CVC/CVV — `Неверный формат`.

Пустая форма проверяется для дебетовой оплаты и оплаты в кредит.

## 4. Структура автотестов

В проекте используются следующие классы:

- `DebitCardTest` — тесты оплаты дебетовой картой;
- `CreditCardTest` — тесты оплаты в кредит;
- `MainPage` — действия на главной странице;
- `PaymentPage` — работа с формами оплаты;
- `DataHelper` — подготовка тестовых данных;
- `SQLHelper` — очистка таблиц и получение статусов из базы данных.

Для дебетовой оплаты используется таблица `payment_entity`.

Для оплаты в кредит используется таблица `credit_request_entity`.

## 5. Используемые инструменты

- **IntelliJ IDEA** — среда разработки Java-проекта.
- **Java 11** — язык разработки автотестов.
- **Gradle** — сборка проекта и управление зависимостями.
- **JUnit 5** — запуск и организация тестов.
- **Selenide** — взаимодействие с веб-интерфейсом приложения.
- **Lombok** — сокращение шаблонного Java-кода.
- **JavaFaker** — генерация тестовых данных владельца карты.
- **Apache Commons DbUtils** — выполнение SQL-запросов и получение статусов операций.
- **Allure** — формирование отчётов о выполнении автотестов.
- **Docker** — запуск приложения и базы данных в контейнерах.
- **Git и GitHub** — хранение исходного кода и управление версиями.

## 6. Возможные риски

- Нестабильность локального приложения или базы данных.
- Неправильные параметры подключения к базе данных.
- Несвоевременное появление уведомления после отправки формы.
- Зависимость тестов от текущей даты при проверке месяца и года.
- Изменение текста сообщений об ошибках.
- Изменение CSS-классов или структуры HTML-элементов.
- Накопление данных в базе при некорректной очистке таблиц.
- Несовпадение версий Java, Gradle или подключённых библиотек.
- Ошибки при параллельном запуске тестов из-за общей базы данных.
